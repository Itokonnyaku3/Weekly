# Tracker v2 — CHANGELOG

## v0.97.1 — UI改善 Phase 4: ジャンプ先を中央に置いて1.1秒光らせる（2026-08-01）

UI改善ハンドオフの **Phase 4**。「↗ や Ctrl+K で飛んだあと、どこに着地したのか分からない」への対処。
既存のジャンプ処理の**末尾に1行足すだけ**で、遷移のロジック（祖先の展開・ズーム解除・日の可視化）は変えていない。

- **`flashEl()` / `landOn()` を追加（`app.js`）**: 着地点を**そのスクローラの中央**に寄せ（`scrollTo` の
  `behavior:'smooth'`）、`data-flash="1"` を 1.3秒だけ付ける。見た目は Phase 1 で入れた CSS
  （`@keyframes flashRing`）側にあるので、JS は付け外しと位置決めだけ。スクローラは
  `#app` / 分割ペイン / 週次の `.wk-scroll` を祖先方向に探して自動判別する。
  連続ジャンプでも毎回光るよう、前のフラッシュを消してから `offsetWidth` を読んでアニメーションを頭から再生する。
  `prefers-reduced-motion` のときは中央寄せも即時（`behavior:'auto'`）にする。
- **適用先（`app.js`）**: `jumpToCard`（Ctrl+K・@チップ・週次の `↗`／Alt+Enter・アジェンダ↗）、
  `zoomToCard`（リストの ↗）、`openProjectAt`（週次の直下ノード／リンク）、`gotoDate`（カレンダー・日付ジャンプ）。
  `zoomToCard` はズーム後にその行が見出しとして先頭に来るため中央寄せはせず光らせるだけ。
  `gotoDate` は既存の `scrollIntoView({block:'start'})` に位置を任せ、**日付見出し**を光らせる。
- **日付見出しは背景を触らない（`style.css`）**: `.day-head` は `position:sticky` なので、フラッシュ終端の
  `background:transparent` を通すと**下の内容が透けて**見える。`flashRingOnly`（リングのみ）を別に用意して当てた。
- 検証: 単体テスト43ファイル全PASS（純ロジック不変）。実機で、週次の `↗` → デイリー着地で該当 `.card-row` に
  `data-flash="1"` と `flashRing` が付き、**行の中心が表示領域の中心と一致**（341px / 340px）、1.3秒後に属性が消えること、
  カレンダーから日付ジャンプで日付見出しに `flashRingOnly` が当たり**背景が不透明のまま**（`rgb(255,255,255)`）
  であることを確認。コンソールエラーなし。

## v0.97.0 — UI改善 Phase 3: 再描画でスクロールとフォーカスを失わない（2026-08-01）

UI改善ハンドオフの **Phase 3**。「タスクを完了にすると画面が先頭へ飛ぶ」という最大の不満点を直した。
触るのは `app.js` の再描画まわりのみで、各ビューの描画ロジックには一切手を入れていない。

- **原因は安全網の `focus()` だった（`app.js`）**: 再描画で DOM が作り直されるとフォーカス中の要素が消え、
  `ensureViewFocus()` の安全網が**ビューの先頭要素**に `focus()` する。この `focus()` が要素を可視域へ入れようとして
  **スクロールを先頭まで引き戻していた**（実測: `scrollTop` 1500 → 0）。安全網とその周辺の退避 `focus()` を
  すべて `focus({ preventScroll: true })` に変更。狙った対象へ戻す分岐（記憶したカード・日付見出し・PJ行）は
  従来どおりスクロールする＝**フォーカス先が画面外なら追う**という既存の挙動は保つ。
- **スクロール位置を描画の前後で控えて戻す（`app.js`）**: `renderAll()` の冒頭で各スクローラの
  `scrollTop`/`scrollLeft` を控え、描画後に同期で戻す。`scrollIntoView` は使わない（親コンテナごと動いて別のズレを生む）。
  対象は `#app` と分割時の各ペイン（`#view-list` ほか）、週次の `.wk-scroll`（毎回作り直されるので都度引き直す）。
  **非分割時のスクローラ `#app` は全ビューで共有**しているため、ビューが変わる再描画では持ち越さない
  （デイリーの位置をリストへ持ち込まない）。内容が縮んだ場合はブラウザ側でクランプされる＝行き過ぎない。
- **フォーカスが消えたときの戻り先を賢くした（`app.js`）**: 再描画前の位置を `focusAnchor()` で控え、
  安全網は**ビュー先頭へ飛ぶ前に**そこへ戻す。`ref` があればその要素、消えていれば**同じ並び順の位置**
  （＝次の兄弟が繰り上がった要素、末尾なら前の兄弟）。チェックボックスや行内ボタンにフォーカスがある状態
  （＝クリックで完了にした直後）は**その行の本文**をアンカーにする。週次は `weekly.js` の `_cursor` に任せて対象外。
- **ツールバーのボタンを押してもフォーカス記憶が消えないように（`app.js`）**: `focusMem` の更新が
  `selectView`/`toggleSplit`/`toggleDone` の入口だけだったため、**ボタンをクリックするとフォーカスがツールバーへ移り**、
  記憶が更新されないまま「記憶なし」として先頭へ退避していた。`focusin` でビュー内に居る間だけ記憶を更新する形に変更。
- 検証: 単体テスト43ファイル全PASS（純ロジック不変）。実機（実データ）で以下を確認、コンソールエラーなし。
  - デイリーで下方スクロール中にチェックボックスで完了 → **スクロール 900 のまま・フォーカスは完了したカード自身**
  - 「完了を隠す」をボタンで実行（フォーカスがツールバーへ移る経路）→ スクロール保持・同じカードにフォーカス
  - 「完了を隠す」ON でカードを完了 → 行が消えても**近傍のカード**に着地（先頭へ飛ばない）・スクロール保持
  - Undo(Ctrl+Z)/Redo(Ctrl+Y) → スクロール・フォーカスとも維持
  - 分割ビュー → 左右のスクロールが独立して保持され、フォーカスは操作した側のペインに留まる
  - 週次で Space 完了 → 縦横スクロールとも保持（横 250 / 縦 300 のまま）
  - ビュー切替（デイリー⇄リスト）で `#app` のスクロールが持ち越されないこと

## v0.96.1 — UI改善 Phase 1: モーション統一・フォーカス可視化・PJ名の可読性（2026-08-01）

UI改善ハンドオフ（`v2/design_handoff_tracker_ui/README.md`）の **Phase 1**。**CSS と PJバッジの色指定だけ**で、
既存ロジックには一切触れていない＝問題があれば当該ルールを消すだけで完全に元へ戻せる。

- **状態遷移を .2s / ease に統一（`style.css`）**: `.card-row` / `.proj-land-row` / `.wk-item` / `.wk-cell` /
  リストの `td` に `transition: background-color .2s ease, box-shadow .2s ease` を指定。
  `transition: all` は使わない（全プロパティを補間して重くなるため）。再描画では DOM ノードが作り直されるので、
  この遷移が走るのは**同じノードのままフォーカスが移るときだけ**＝描画コストは増えない。
- **デイリーのフォーカス行にも左端3pxの青ライン（`style.css`）**: `.card-row:focus-within` はこれまで淡い面
  （`--accent-soft`）だけで、選択行（`.card-row.selected`）にある左端のラインが無かった。同じ手掛かりを付けて
  「今どこにカーソルがあるか」を線でも示す。値は `.selected` と同一なので、どちらの規則が勝っても見た目は変わらない。
- **着地フラッシュの土台（`style.css`）**: `@keyframes flashRing` と `[data-flash="1"]` を追加（点ける JS は Phase 4）。
  リング色・背景色はテーマ変数 `--flash-ring` / `--flash-bg` / `--flash-bg2` に持たせ、**ダークテーマでも白飛びしない**。
- **PJバッジを灰色からPJカラーへ（`daily.js`・`style.css`）**: デイリー行末の `#PJ名` が `--tx3`（灰）だったため、
  「薄い＝副次情報」で読み飛ばされていた。`colors.js` の `projColor()` を `--pjc` で渡し、**リスト・週次と同じ色**に統一。
  「小さいから副次情報」で階層を作る方針。色が引けない場合は従来の灰色にフォールバックする。
- **`prefers-reduced-motion` に対応（`style.css`）**: OSで「視差効果を減らす」を選んでいる場合はアニメーションと
  遷移を実質無効化（`.01ms`）。
- 検証: 単体テスト43ファイル全PASS（純ロジック不変）。実機（実データ 78行・PJバッジ25個）で、
  バッジがPJごとに色分けされること（`#TEC新レジ`=緑 / `#プロジェクト未満`=橙、リスト・週次と同色）、
  `.card-row` の遷移が `background-color .2s, box-shadow .2s` になっていること、
  フォーカス行が `#eaf1fe` ＋ `inset 3px 0 0 #2c6df0` になることを確認。コンソールエラーなし。

## v0.96.0 — メモにもPJバッジ／週次セルの並び順を選べるように／週次のPJ行を折りたたみ（2026-07-28）

- **メモにも所属PJのバッジを出す（`daily.js`）**: `appendBadges()` が `kind !== 'task'` で即 return していたため、
  PJを持つ**メモだけ右側に `#PJ名` が出ず**、行を見ただけではどのPJの話か分からなかった。メモも対象にした。
  優先度・期限のバッジは従来どおりタスク限定（メモの `due` は当日リマインダ用で意味が違うため）。
  PJ未割当のメモはこれまでどおりバッジなし。
- **週次セルの並び順を選べるように（`week.js`・`weekly.js`）**: ツールバーに「並び」を追加
  （**既定（優先度→期限）／名前順／期限順／新しい順**）。既定は従来と同じ並びなので**デグレなし**。
  これまでは既定しかなく、期限が同じカードは**出所の日付**で順位が決まるため、同じ期限のタスクが並ぶセルでは
  順序が読み取れなかった（「並びがバラバラ」）。名前順は**表示テキスト（`#マイルストーン` を除いた形）**で比較し、
  数字は数値として扱う（`項目2` < `項目10`）。どのモードも最後は名前→id で決着させる＝**同じデータなら常に同じ並び**。
  選択は `localStorage`（`pwt2_wkSort`）に保存＝undo履歴・GitHub同期には乗せない表示設定。
- **週次のプロジェクト行を折りたたみ（`week.js`・`weekly.js`）**: `Ctrl+↑` で折りたたみ、`Ctrl+↓` で展開。
  デイリーのカスケード折りたたみと同じキーで、**1回目は手元の行だけ・2回目で全プロジェクト**に効く
  （折りたたみ: フォーカス行が開いている→その行だけ／すでに畳まれている→全部畳む。
  展開: フォーカス行が畳まれている→その行だけ／すでに開いている→全部開く）。判定は純ロジック `rowCollapseStep()`。
  畳んだ行は週セルが**件数サマリ1行**（`🏁1 □8 ✓2 📝1 ↩1`）になり、行の高さが 334px → 27px に縮む。
  PJ列の `▾`/`▸` クリックでも同じトグル。サマリは Enter/クリックでその行を開く。
- **折りたたみまわりの取りこぼし対策**: 畳む行に展開中のセル（Alt+↓ の実体アウトライン）があれば**展開を解除**する
  （行ごと消えてフォーカスが迷子になるため）。畳んだ行のセルも**ドロップを受ける**＝D&D の死角を作らない。
  各セルにフォーカス枠を必ず1つ置くのでカーソル移動（`shape.counts`）も壊れない。
  保存は `pwt2_wkCollapsed`。消えたPJのIDは読み込み時と判定時に落とす（残骸で「全部畳む」判定が狂わない）。
  コマンドパレット（Ctrl+K）にも「プロジェクト行を折りたたむ／展開」を追加＝キー操作と同じ実体を呼ぶ。
- 検証: 単体テスト43ファイル全PASS（`week.sort` / `week.collapse` を新規追加）。実機で、メモのPJバッジ表示、
  並び「名前順」での整列（かな→漢字の読み順・`項目2` < `項目10`）と再読込後の保持、
  `Ctrl+↑`×2 → `Ctrl+↓`×2 の往復が仕様どおり戻ること、畳んだ行への D&D、
  展開中セルを含む行を畳んだときの解除を確認。コンソールエラーなし。

## v0.95.4 — 日付の判定を日本時間（UTC+9）に統一（2026-07-27）

- **「今日」が朝9時までズレていた不具合を修正（`time.js` 新規）**: 各所で `new Date().toISOString().slice(0,10)` を
  使って日付を作っていたが、`toISOString()` は **UTC 整形**のため **JST 00:00〜08:59 の間は前日の日付**を返していた。
  実測: JST 2026-07-27 08:42 → `2026-07-26`。日付の基準を持つモジュール `time.js` を新設し、
  `todayStr()`（今日）と `dateOf(値)`（時刻値→その日）に一本化した。オフセットは `TZ_OFFSET_MIN = 540` の1箇所。
  日本には夏時間が無いので固定値でよく、実行環境のTZに依存しない（`getUTC*` で読む）。
- **影響していた「今日」判定（`app.js`・`list.js`・`project.js`・`search.js`・`weekly.js`）**: 朝9時前は
  デイリーの「今日へ移動」「今日にタスク追加」が前日の日カードを指し、期限の「今日／明日／来週」が1日手前に付き、
  リスト・検索・PJビューの期限フィルタ（今日まで/期限切れ）が1日ずれ、**週次ビューの「今週」列が前の週**を指していた。
  今日は月曜のため影響が最大で、`weekStart('2026-07-26')` = `2026-07-20`（先週）になっていた。
- **保存済みデータの日付換算も修正（`week.js`・`query.js`・`list.js`）**: `createdAt` / `doneAt` は UTC の ISO で
  保存されるため、`.slice(0,10)` で日付を取ると同じく前日になっていた。`dateOf()` を通す形に変更＝**過去に保存した
  データも正しく読める**（保存形式は UTC のまま変えないので、同期・競合判定・並べ替えには影響しない）。
  これにより「JST 朝8時に完了したタスクが週次ビューの『やったこと』で前の週に入る」「完了日での絞り込みが1日ずれる」
  「リストの作成日列が前日になる」が直った。
- **日付整形の重複を解消（`daily.js`・`calendar.js`・`github.js`）**: ローカル時刻で自前整形していた4箇所
  （Ctrl+/ の日付挿入・`@今日`/`@明日`・カレンダーの今日・日次バックアップ名）も `time.js` 経由に統一。
  JST環境では従来と同じ結果＝挙動は変わらないが、日付の決め方が1本になった。`calendar.js` の未使用 `ymd` を削除。
- 検証: 単体テスト41ファイル全PASS（`time.test.mjs` を新規追加。`week.cardweek` / `query` には
  JSTで日付・週が変わるケースを追加し、**修正前に失敗する**ことを確認してから修正）。
  実機（JST 08:49）で `todayStr()` = `2026-07-27`（旧実装は `2026-07-26`）、週次ビューの「今週」が **7/27〜8/2**、
  カレンダーの今日ハイライトが 27 日であることを確認。コンソールエラーなし。

## v0.95.2 — リストのフォーカスを反転表示／週次ビューの行をPJカラーの淡色に（2026-07-26）

- **プロジェクト色を共通モジュールへ（`colors.js` 新規）**: `list.js` にあった `projColor` を依存なしの純モジュールへ移し、
  リスト（見出しの色地）と週次ビュー（行の背景）が**同じ色**を使うようにした。`list.js` は互換のため再エクスポート

  `td.style.background` で**インライン**指定していたため、フォーカス時のCSS（`background:var(--accent-soft)`）が
  インラインに負け、彩度の高い色地に細いリングが乗るだけで判別できなかった。PJ色を **CSS変数 `--pjc`** で渡す形に変え、
  フォーカス時は**反転**（PJ色の地＋白文字 → 明色地＋PJ色の文字＋3px の太枠）で示すようにした。
  行フォーカス指定と詳細度が同じため、CSS上は必ずそれより後に置いている。
- **週次ビューの行背景をPJカラーの淡色に（`weekly.js`・`style.css`）**: 各行に `--pjc` / `--wk-tint`（α0.10）/
  `--wk-tint2`（α0.18・PJ列）を設定し、下地の上に**半透明で重ねる**＝ライト/ダーク両テーマで馴染む。
  PJ列は左端に3pxの色帯を付けてリストの色地と対応づけた。未割当行はグレー（`PROJ_NONE_COLOR`）でリストと一致。
  セル自身は不透明を保つ（左固定列の下を他の列が透けないようにするため）。
  今週列のハイライトは不透明色だとPJカラーを隠してしまうため、半透明の `--wk-now`（テーマごとに値を持つ）を重ねる方式に変更。

  フォーカス＝白地＋PJ色文字＋3px枠の反転、週次の行ごとの色（PJ列0.18＋色帯・週セル0.10・未割当グレー・下地不透明）、
  今週列でPJカラーが残ること、ダークテーマでの可読性を確認。コンソールエラーなし。

- **データモデル**（`src/store.js` / `createStore` ファクトリ）
  - 本体（body）＝中身＋固有属性、付箋（ref）＝画面に出る配置でツリーを保持
  - `createCard`（本体＋最初の付箋を原子的生成）／`getBody`・`getRef`・`updateBody`・`updateRef`
  - `childRefs`（順序付きツリー）／`refsForBody`／`deleteRef`（子の連鎖削除＋参照ゼロで本体GC）
  - `queryBodies`（リストビュー用レンズ）／`ensureDayCard`（日カードの確保・重複生成なし）
- **永続化**（`src/persist.js`）: localStorage へデバウンス保存／起動時に復元
- **外枠**: `index.html`・`style.css`・`src/app.js`（ESモジュール、`package.json` `type:module`）
- **検証**: 単体テスト5本（`tests/*.mjs`）すべて緑。ブラウザで「作成→保存→再読込で復元」を確認（`seq` 引き継ぎ含む）。
