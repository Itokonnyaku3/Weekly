# AI連携機能（バックログ・第3段）

2026-09-06 に要望を受領。**第2段（到達性）の完了後に着手する。**

## 前提・制約

- 予算感: **月 100〜200円程度**。使用頻度は高くない
- 実現手段は未定。Claude API（従量課金）でも他サービスでもよい
- v2 はビルドなしの素の ES モジュール＋ブラウザ完結。APIキーの置き場所は設計課題（localStorage に置くと公開リポジトリの Pages 経由で使う際に露出リスクがある。要検討）

## ① デイリーの内容を整理してタグを付ける

- デイリーに書かれた内容を読んで、必要に応じてタグ（プロジェクト／会議など）を付与する
- **判断できないものは「確認リスト」を作り、ユーザーに判断させる**（勝手に決めない）
- 背景: ユーザーは「メモした時点ではどの切り口でチェックしたいか分からない」ため、書く時点での正しいタグ付けは原理的に不可能。**後追いでの整理をAIが担う**のが本機能の狙い

## ② ライブクエリキャンバスの自動生成

- ユーザーのリクエスト（自然言語）に応じて、欲しい情報を整理したキャンバスを作る
- 例: 「今月の稟議の進捗をまとめて」→ 該当カードを集めたビューを生成
- 既存の `v2/src/query.js` の条件モデル（`{ groups:[{ keyword, tags[], proj, mid, due, done, prio }] }`）に落とし込む形になるはず。**自然言語 → query オブジェクトへの変換**が本体
- 第2段で作る「保存クエリ／俯瞰ビュー」の仕組みが土台になる

## 設計上のつながり

②は第2段の成果物（クエリで組む俯瞰ビュー）の上に載る。①は第2段で「タグが付いていれば拾える」状態を作った後、そのタグ付けを自動化するもの。**したがって第2段 → ① → ② の順が自然。**
