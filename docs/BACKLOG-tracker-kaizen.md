## 原因が特定できているもの

**⑥** — `v2/src/daily.js` の `dailyZoomHandlers`:

```js
onZoomOut: (refId, pos) => { zoomOut(store); requestRender(); focusCard(refId, pos); },
```

`refId` は「ズームアウト前に編集していたカード」。ズームアウト後は、出てきたノード（＝直前の `_focusRef`）にフォーカスすべき。見出し行から `Alt+↑` を押した場合は `refId` が旧ルートと一致するため既に正しく動くが、子カードから押すと引きずられる。

## ⑤の位置づけ

**⑤は第2段（到達性）の中核であり、単なるUX要望ではない。**

種類=画像で47枚を一覧できるようにした直後に「それが何の画像か分からない」という指摘が出たのは当然で、**到達できることと、それが何か分かることは別**である。検索結果・棚卸し画面のどちらもカードの出所の文脈を必要とするため、⑤を先に片付けると項目2（棚卸し）が作りやすくなる。

現状、検索結果は出所の日付ごとにグルーピングされているだけで、日より下の階層（どのカードの下にあったか）は表示されない。

## ①のエフェクト仕様（本人指定・2026-09-06）

メッセージ（「1件を完了にしました ↶ 元に戻す」）を出すことには同意を得たが、**エフェクトも併せて必要**との回答。「折り畳みも同様なので、それはそれとして見てみたい」。

完了操作の演出は、次の順序で行う。

1. **取り消し線が出る**
2. そのあと **ふわっと消える**（フェードアウト）
3. 消えたあと **スムーズにスクロール**（下の行が滑らかに詰まる）

いきなり消えるのではなく、①→②→③と段を追うことが要件。②（折り畳み・展開）も同じ考え方で演出を付ける。

**実装前に、動くプロトタイプを見せて速度と手触りを確認してもらう。** タイミング（各段の長さ）は文章では決められないため。

## 推奨する順序

1. **③⑥** — 小さいバグ。第1段（信頼性）の続きとして先に潰す
2. **⑤** — パンくず。第2段の要。項目2の前提にもなる
3. **第2段 項目2** — 無タグの塊の棚卸し
4. **①②** — 手触りのフィードバック。「消えたように見える」不安の解消は信頼性に効く
5. **⑦** — 画像付きノードのコピペ
6. **④** — ビュー間の操作統一。設計から必要で規模が大きい。②までの改善で体感が変わってから判断するのが良い
